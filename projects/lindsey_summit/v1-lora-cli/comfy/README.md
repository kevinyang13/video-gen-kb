# lindsey_summit in ComfyUI

Generated by `scripts/comfy_export.py lindsey_summit`. Regenerate any time the
spec changes; nothing here is edited by hand.

| file | what it is |
|---|---|
| `lindsey_summit_still.json` | FLUX.2 [klein] text-to-image + LoRA. Workflow > Open, or drag onto the canvas. |
| `lindsey_summit_i2v.json` | LTX-Video image-to-video. Same. |
| `lindsey_summit_shots.json` | All eight shots as plain data -- prompts, LoRA weights, trims, locks. |

Shot s1 is loaded into the prompt boxes of both graphs. The other seven live in
the Note node on each canvas; switching shot is copy, paste, and set the LoRA
weight.

## The LoRA does not transfer

`lindsey_lora_2000_lora_f32.ckpt` is not a PyTorch checkpoint despite the
extension. It is a SQLite database:

```
$ file lindsey_lora_2000_lora_f32.ckpt
SQLite 3.x database
$ sqlite3 ... ".schema"
CREATE TABLE tensors (name TEXT, type INTEGER, format INTEGER,
                      datatype INTEGER, dim BLOB, data BLOB, PRIMARY KEY (name));
$ sqlite3 ... "SELECT name FROM tensors LIMIT 2;"
__dit__[t-x_embedder-0-0]__down__
__dit__[t-x_embedder-0-0]__up__      -- 564 tensors
```

That is Draw Things' own container format. **ComfyUI cannot load it**, and the
`LoraLoaderModelOnly` node in the still workflow points at a `.safetensors` name
that does not exist yet. Until it does, the workflow runs but renders a generic
child, not Lindsey.

Three ways out, cheapest first:

1. **Retrain for ComfyUI.** Train the same dataset with a ComfyUI-native trainer
   (kohya / ai-toolkit / SimpleTuner) and get safetensors directly. The dataset
   is already built and captioned at
   `projects/lindsey_lora/v1-photo-dataset/seed/dataset` -- 32 pairs, trigger
   `lindsey_kx`, class word `girl`. This is the only option that is certain to work.
2. **Convert the tensors.** The data is all there: 564 down/up pairs, readable
   with `sqlite3` and `numpy.frombuffer`. The work is mapping Draw Things'
   `__dit__[t-c_q-0-0]__down__` names onto the key names ComfyUI's FLUX LoRA
   loader expects, which is a per-layer mapping that has to be derived and then
   tested. Untested as of 2026-10-01.
3. **Keep the stills in Draw Things.** Render stills with `film_run.py` where
   the LoRA already works, then bring the PNGs into the i2v workflow via its
   `LoadImage` node. The i2v graph needs no LoRA at all -- LTX never sees one --
   so this half transfers with nothing lost.

Option 3 is the honest recommendation. The LoRA is the only thing that does not
port, and the video stage is the half that does.

## Model files

The loader nodes carry filenames, not downloads. Put the real ones in ComfyUI's
`models/` tree and repoint each node if your names differ:

```
models/diffusion_models/flux2-klein-9b.safetensors
models/text_encoders/mistral3_flux2_text_encoder.safetensors
models/vae/flux2-vae.safetensors
models/checkpoints/ltx-2.3-22b-distilled.safetensors
models/text_encoders/t5xxl_fp16.safetensors
models/loras/lindsey_lora_2000.safetensors          <- does not exist yet, see above
```

The LTX nodes (`LTXVImgToVideo`, `LTXVConditioning`, `LTXVScheduler`,
`LTXVAddGuide`) come from the **ComfyUI-LTXVideo** pack, installed through
Manager. Class names in that pack have changed between releases -- if a node
loads red, it was renamed; replace it from the node search and reconnect. The
graph around it is correct either way.

## Settings carried across

Taken from `spec.json`, not retyped:

| stage | settings |
|---|---|
| still | FLUX.2 [klein] 9B, 1024x576, 4 steps, CFG 1.0, shift 3, ddim_uniform |
| i2v | LTX-2.3 22B distilled, 1024x576, 249 frames @ 25 fps, 8 steps, CFG 1.0, shift 5.0 |

CFG 1.0 is not a mistake -- klein is distilled and higher CFG burns it. The
still graph's negative branch is a `ConditioningZeroOut` for that reason: at
CFG 1 the sampler never evaluates it, so a real negative prompt there would
look like it was doing something it is not.

ComfyUI has no equivalent to LTX's stochastic sampling gamma (0.3 in Draw
Things). Nearest control is the LTXVScheduler's stretch/terminal pair. Expect
clips to differ slightly from the delivered film even at matching seeds.

## Per-shot settings

| shot | LoRA | keep | still input |
|---|---|---|---|
| s1 | 0.85 | 9.5 s | forest master |
| s2 | 1.0 | 7.0 s | lindsey master |
| s3 | 0.6 | 8.0 s | lindsey master |
| s4 | 1.0 | 7.5 s | lindsey master |
| s5 | none | 8.0 s | stair master |
| s6 | 0.85 | 9.5 s | stair master |
| s7 | 1.0 | 7.5 s | lindsey master |
| s8 | 0.85 | 8.0 s | summit master |

65.0 s of clip, less seven 0.75 s crossfades, delivers 59.75 s.

Face shots (s2, s4, s7) are at weight 1.0 and cut at 7.0-7.5 s because frontal
face clips drift at around eight seconds regardless of the motion prompt. The
long takes go to backs, macro and landscape. Keep that discipline in ComfyUI --
it is a property of the video model, not of Draw Things.
